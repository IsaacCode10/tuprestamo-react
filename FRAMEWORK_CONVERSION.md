# Framework de Conversión — Tu Préstamo Bolivia

Documento vivo, construido junto con Isaac (no asumido de antemano — ver
`CLAUDE.md`). Toda decisión que toque algo que el prestatario o el
inversionista ve o siente (copy, layout, orden de secciones, un mensaje de
WhatsApp, un correo, un cupón) se fundamenta primero acá — no en gusto
personal. `BRAND_KIT.md` define el tono y el estilo visual; este documento
define la lógica de persuasión y de dónde/cómo colocar cada cosa.

Adaptado de la versión de Capibara Kids (`../Proyecto Capibara
Kids/capibara-kids-ecommerce/FRAMEWORK_CONVERSION.md`), pero **no es una
copia** — el modelo de negocio es distinto (financiamiento colectivo de
deuda vs. producto físico con stock), así que cada principio se validó de
nuevo contra lo que es real hoy en Tu Préstamo, no contra lo que era real
en Capibara Kids.

## Particularidad de Tu Préstamo: dos públicos, dos emociones

A diferencia de Capibara Kids (un solo público), acá conviven dos funnels
con estados de ánimo opuestos, y un mismo principio de Cialdini casi seguro
necesita un gatillo distinto para cada uno:

- **Prestatario**: actúa desde alivio/urgencia — quiere dejar de sangrar en
  intereses de tarjeta.
- **Inversionista**: actúa desde cálculo — quiere rendimiento, y su primera
  pregunta es "¿es seguro mi dinero?".

Cualquier aplicación de un principio de abajo debe decir explícitamente
para cuál de los dos es, o si aplica a ambos con el mismo copy.

## 1. Cialdini — principios de persuasión (el QUÉ)

| Principio | Estado en Tu Préstamo | Detalle |
|---|---|---|
| **Reciprocidad** | ✅ Ya implementado (parcial) | El Auditor de Tarjetas gratis (`/auditor-de-tarjetas`) ya funciona como esto — le damos algo de valor real primero, sin pedir nada a cambio. **Pendiente de sumar**: cupón de referido gana-gana (el que refiere gana, el referido gana) — se implementa recién cuando cerremos al primer cliente real (candidato: Adhemar Rodo Sosa). No se construye antes por gusto — se construye cuando haya un cliente real al que aplicárselo. |
| **Prueba social** | ⏳ Pendiente, bloqueado | No inventamos testimonios (regla de autenticidad, ver abajo). El primer testimonio real depende de una cadena de eventos que todavía no cerró: constituir la SRL → alta en INFOCRED → cerrar al primer cliente (Adhemar Rodo Sosa es el candidato natural, es el único lead que completó toda la documentación). Recién ahí hay un caso real, con nombre y permiso, para mostrar. |
| **Autoridad** | ✅ Definido | La autoridad de Tu Préstamo **es la historia personal de Isaac** (11 años con la tarjeta, el viaje al Mundial 2014, "Finanzas de Isaac") — no un aval institucional. La SRL en trámite de constitución es un refuerzo secundario posible a futuro, no el eje. **Regla de copy explícita: cuando se use la historia como autoridad, se habla en términos de beneficio para quien lee ("por eso entiendo lo que te está pasando"), nunca como una lista de características o hitos del fundador.** |
| **Escasez** | ⛔ No se usa todavía (MVP) | Decisión explícita: no fabricar escasez. El financiamiento es colectivo, así que sí existe un cupo real e imaginario de cuánto se puede fondear por mes — pero hoy el volumen de solicitudes es demasiado bajo para que comunicar un "cupo mensual" sea honesto. Se retoma cuando el volumen de solicitudes reales lo justifique. |
| **Compromiso y coherencia** | ⏳ Sin explorar todavía | Terreno pendiente — candidato natural: el Auditor de Tarjetas o la Calculadora como primer micro-compromiso antes de la solicitud completa (ya son, de hecho, un primer paso — falta nombrarlo así en el copy/flujo). |
| **Simpatía** | ✅ Ya presente, informal | Tono boliviano cercano de "Finanzas de Isaac" y del copy en general (ver `BRAND_KIT.md`). No se ha auditado todavía todo el sitio con este lente específico. |
| **Unidad** | ❓ Sin definir | Isaac no tiene todavía una respuesta acá — queda abierto explícitamente, no se rellena con una suposición. Ver nota abajo. |

**Nota sobre Unidad (abierta, no resuelta):** una hipótesis para conversar
en otra sesión, no una decisión: con dos públicos tan distintos, "unidad"
podría no ser un solo grupo compartido sino dos ("bolivianos que ya
entendieron cómo funciona realmente una tarjeta de crédito" para
prestatarios, "bolivianos que invierten en su propio país en vez de mandar
la plata afuera" para inversionistas) — o puede que unidad simplemente no
sea una palanca relevante para este negocio todavía. Pendiente de decidir
con Isaac, no antes.

## 2. LIFT Model (MECLABS) — el DÓNDE y CÓMO

Pendiente de trabajar junto con Isaac — todavía no se discutió principio
por principio como se hizo arriba con Cialdini. No se rellena por
adelantado para no repetir el error de asumir un framework antes de
tiempo. Cuando se converse, mantiene la misma estructura que la versión de
Capibara Kids (Propuesta de valor, Claridad, Relevancia, Urgencia,
Ansiedad, Distracción), evaluada por separado para el funnel prestatario y
el funnel inversionista donde haga falta.

## Checklist obligatorio antes de cualquier cambio visible al cliente

1. ¿Qué principio de Cialdini estoy usando acá, según la tabla de arriba?
2. Si el principio está marcado "pendiente" o "no se usa todavía" arriba,
   **no se usa** — no se improvisa una versión propia sin conversarlo antes.
3. ¿Es para el funnel prestatario, el inversionista, o ambos? ¿El gatillo
   emocional es el correcto para ese público (alivio/urgencia vs. cálculo)?
4. ¿Sigue siendo real? (ver regla de autenticidad abajo)
5. ¿Cumple el tono y el sistema visual del `BRAND_KIT.md`?

## Regla de autenticidad (no negociable)

Igual que en Capibara Kids, Tu Préstamo elige ser real antes que inflar
números. Nunca:
- Escasez o urgencia fabricada — hoy directamente no se usa (ver tabla).
- Testimonios inventados — el primero llega cuando cierre un cliente real,
  con nombre y permiso confirmado.
- Aval de autoridad institucional que no se tenga de verdad — la SRL en
  trámite no se presenta como si ya estuviera constituida.

## Cómo registrar decisiones nuevas

Cuando se tome una decisión nueva usando este framework, documentarla en
`STATUS.md` (fecha, qué cambió, por qué) y actualizar la tabla/pendientes
de este documento — así crece con el proyecto real en vez de quedar en
teoría, igual que en Capibara Kids.
